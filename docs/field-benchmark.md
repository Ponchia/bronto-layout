# Independent real-world layout benchmark — capture and labeling protocol

The controlled fixtures in `benchmarks/audit-controlled-*.json` are useful
regression tests but are **not** independent evidence of production accuracy.
This workflow separates a live browser capture from human ground truth so
neither labels nor negative cases can silently be inferred from the CLI.

## Dataset and evidence

`benchmarks/field-sites.v0.1.json` proposes 30 viewport states from five
first-party sites/routes: the personal website, Sense6 English, Sense6 Arabic,
Sense6 Learn and Chiara's portfolio preview, at 320, 360, 375, 430, 768 and
1280 CSS pixels. These sites are mutable. The manifest is a **planned cohort,
not 30 independently scored cases**. It uses an explicit HTTPS hostname
allowlist; URLs with credentials, query strings or fragments are rejected.

First validate the manifest, then capture the entire cohort or a subset:

```sh
npm run field:validate
node scripts/field-benchmark.mjs capture \
  --manifest benchmarks/field-sites.v0.1.json \
  --out reports/field-2026-10-12
node scripts/field-benchmark.mjs capture \
  --manifest benchmarks/field-sites.v0.1.json \
  --ids portfolio-375,sense6-ar-375 \
  --out reports/field-smoke-2026-10-12
```

On development boxes where Chromium cannot retain its security sandbox, do **not**
run public sites with `--no-sandbox` merely to obtain a score. Instead, manually
trigger the GitHub Actions **Manual first-party field benchmark capture**
workflow. Its disposable GitHub runner can use the documented opt-in Chromium
flag for the tightly allowlisted public websites. Supply `all` for the full
cohort or a comma-separated selection. Download the workflow artifacts and
review them locally; no ground-truth labels are generated by CI. Artifacts
may be visible to people with repository Actions access, so never use this
workflow for private pages or sessions.

Use a new output directory for every run. The collector never overwrites
existing evidence. Each case stores `audit.json`, a raw initial-viewport PNG,
and an index with content SHA-256 hashes, width, page URL, exit code, tool
version, Node version, browser user agent, final browser URL, source revision and timestamp. A screenshot is not an assertion that
the full page was visible: it covers the **initial viewport only**. The
reviewer must also scroll the real page and inspect interactive or below-fold
content. Incomplete browser observations are explicitly preserved and never
scored as negatives.

The browser sandbox stays enabled by default. Only the existing opt-in
`--no-sandbox`/`BRONTO_CHROME_NO_SANDBOX=1` escape hatch is available for
trusted isolated test environments, never recommended for unknown sites.
Screenshots can expose personal data: capture only permitted pages and do not
commit/share raw reports without review. The `reports/` path is gitignored.

## Prepare an independent-review worksheet

After downloading the captured artifacts, generate a human-readable review sheet that verifies the screenshot/report hashes without disclosing automated issue predictions as labels:

```sh
node scripts/field-benchmark.mjs review-packet \
  --captures reports/field-2026-10-12 --out reports/field-review-worksheet.md
```

The command never invents human judgments. It leaves checkboxes blank, flags incomplete evidence, and refuses to overwrite an existing worksheet. The reviewer must visit the rendered page as well as the initial-viewport screenshot, include below-fold/interactive states and manually supply evidence and intent. The worksheet deliberately does **not** copy predictions from the CLI report to avoid anchoring the reviewer.

## Optional frame-evidence capture and scoring protection

For an allowlisted public-site capture, enable `--frame-inventory` only when frame coverage is relevant:

```sh
node scripts/field-benchmark.mjs capture \
  --manifest benchmarks/field-sites.v0.1.json \
  --ids chiara-preview-375 --frame-inventory --out reports/chiara-frame-2026-10-12
```

The exact case IDs are defined by the manifest. On a shared devbox that cannot retain the Chromium sandbox, run the manual GitHub Actions **Manual first-party field benchmark capture** workflow instead, with its `frame_inventory` option, inside the allowlisted disposable runner. Do not disable the browser sandbox to inspect an arbitrary public URL on a shared host.

Chromium's frame-tree and DOMSnapshot data show **which frame documents were observed in a snapshot**; they do not establish whether their inner contents rendered correctly. The audit retains `embedded-frame-uninspected` review warnings. Frame IDs are ephemeral, captured document counts are bounded, and HTML/canvas/shadow/paint-order completeness is not inferred. URL credentials, query strings and fragments are stripped from frame inventory output.

**Capture integrity and diagnostic completeness are distinct.** The capture index may record `complete: true` when a screenshot and top-level audit were successfully acquired, even if an iframe was not inspected. `contentCoverage` documents that limitation; the field scorer excludes reviewed cases with `known-uninspected-content` from whole-page detector accuracy denominators. Historical captures without `coverage.status` still use `embeddedFrames` to avoid silently counting missing interior observations as true negatives. The scorer reports these separately under `coverageExcluded`. Labels are never inferred from Chromium data.

## Label independently

Before consulting `audit.json` findings, a named human reviewer should
inspect the page, screenshots, DOM and computed styles, and record whether
each supported detector category actually applies in the observed state.
Separate intentional design decisions from genuine failures and mark cases
unreviewable when reliable judgment is not possible. Record `reviewer`,
`reviewedAt`, `rationale`, and the page/width/state. Do not use the output of
Bronto Layout to generate the expected labels.

Copy `benchmarks/field-labels.template.json` to an untracked file. For every
reviewed case, add a record like:

```json
{
  "id": "portfolio-375",
  "reviewStatus": "reviewed",
  "reviewer": "Human reviewer identifier",
  "reviewedAt": "2026-10-12",
  "rationale": "Document concrete visual/DOM evidence and intentional exceptions.",
  "reviewedScreenshot": true,
  "reviewedRenderedPage": true,
  "expectedMeasured": [],
  "expectedReview": []
}
```

The empty arrays above are a **schema illustration**, not labels for that
site. For unreviewable cases, omit expected arrays and explain why.
Missing case labels remain pending, not implicitly healthy. The review
attestation is a protocol requirement rather than automated proof that the
review was independent.

## Score separately

```sh
node scripts/field-benchmark.mjs score \
  --captures reports/field-2026-10-12 \
  --labels reports/field-manual-labels.json \
  --json --report reports/field-score.json
```

Per-detector confusion matrices reuse the controlled benchmark scoring
semantics. Reviewed cases with incomplete or changed screenshot/report hashes
are excluded and explicitly counted. No reviewed cases means no score. A
missing positive denominator yields `null`, never a fabricated 100% score.
`--assert` refuses missing/unreviewable browser evidence and unreviewed
case coverage, and fails on classification mismatches.

Before competitive claims, broaden beyond first-party sites with permission,
obtain genuinely independent labels, compare Snug and other tools on identical
states, browsers and viewports, and report both false positives and missed
problems. We do not currently have that external comparison.
